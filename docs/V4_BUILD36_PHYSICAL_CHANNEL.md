# Format-v4 Build36 physical-channel checkpoint

Build36 analyzes the first real paper corpus generated by the Build35 scanner-first pack. The three prints use the active MQ carrier at robust profile, strength 24, with one unmarked control and the authenticated payloads `v4-b35-phys-a` and `v4-b35-phys-b`.

## Acquisition actually available

The office scanner used for the experiment cannot emit color PNG/TIFF. Its useful color mode produced JPEG at 600 dpi. Alternative PDF and PowerPoint modes were inspected but internally contained lower-resolution/lossier raster images and were not adopted as the primary corpus. The 600-dpi JPEG scans are therefore the official first Build35 physical scanner evidence.

This deviates from the original 300-dpi lossless acquisition plan. The deviation is recorded rather than hidden or normalized away.

## Blind result

The Build35 blind projective decoder rejects the unmarked control as required, but it also rejects marked A and B. The failure is geometric: physical pilot evidence is weak enough that the broad Build34 projective search can select a false basin before frame decoding. Lowering the Build29 acceptance thresholds would make the gate less safe and is not accepted as a solution.

## Channel-isolation diagnostic

A private diagnostic registered each marked scan against its corresponding generated digital carrier. This registration is **not available to a blind PixSeal decoder** and therefore cannot count as physical qualification or pilot promotion. It was used only to answer a narrower question: did print + paper + scanner + JPEG preserve enough signal to authenticate the existing v4 frame if geometry is correct?

Yes. With geometry supplied independently, signed DCT observations from both marked scans are sufficient for deterministic soft Hamming(7,4) decoding and exact HMAC authentication:

- marked A -> `v4-b35-phys-a` -> HMAC PASS;
- marked B -> `v4-b35-phys-b` -> HMAC PASS.

The hard-decision Hamming path remains just beyond its guaranteed radius on several weak words. Build36 therefore retains signed margins and performs maximum-likelihood selection among the 16 legal Hamming(7,4) codewords per word. The old hard decoder remains a fallback.

## What Build36 does not change

Build36 does not change the v4 pilot identity, encoder, strength 24, 64/1120 pilot/data partition, Hamming code, whitening, frame bytes, CRC/HMAC domains, Build29 geometry acceptance floors or any frozen Format-v3 source file. Soft decoding starts only after blind geometry has already been accepted.

## Scientific conclusion

The first real Format-v4 print/scan experiment no longer points to insufficient strength or insufficient ECC as the primary blocker. The existing signal can cross the physical channel and authenticate. The remaining blocker is specifically **blind scanner registration** accurate enough to preserve the 8-pixel DCT lattice. The existing paper prints should be kept; no reprint is required for the next build.

## Build37 follow-up

Build37 closes the blind-registration blocker described above on the same unchanged 600-dpi JPEG corpus. The full-page paper/artwork boundary seeds a narrow scanner-affine search, disjoint public-pilot halves qualify the basin, a complete-pilot `(0,0)` gate rejects aliases, and a five-geometry pilot-qualified ensemble feeds the Build36 soft decoder. The control rejects and both marked scans HMAC-authenticate. See [`V4_BUILD37_BLIND_SCANNER.md`](V4_BUILD37_BLIND_SCANNER.md).
